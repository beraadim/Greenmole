# 1.6.1-private.4

Built and deployed on Oberon on 2026-10-15, replacing `1.6.1-private.3` in the
existing `windows11-guac-lab` Compose project. This remains an internal build
of Apache's unreleased 1.6.1 staging baseline.

## Changes

- Clipboard synchronization now gates remote input through one ordered queue
  per client view. It removes per-event polling timers and keeps the local
  pointer responsive while the clipboard is being read. Only adjacent free
  pointer movements can replace each other while waiting; clicks, releases,
  keyboard input, wheel events, and held-button dragging retain their order.
  Overlapping clipboard operations keep the gate blocked until all finish,
  and detached/destroyed views discard their queued input.
- Browser catch-up renders complete frames in order, then yields after eight
  milliseconds or sixteen complete frames, whichever comes first. Each frame
  remains atomic, including a frame whose drawing exceeds eight milliseconds.
  This gives input and other browser work opportunities to run during a burst
  without exposing a partly rendered Guacamole frame. Frame acknowledgements
  retain the correct timestamps/counts, and asynchronous image completion
  resumes blocked rendering.
- RDP sessions advertise a versioned private `x-resync` snapshot extension.
  The browser can request the current committed display for that user, without
  reconnecting or sending desktop input. The **Display → Refresh display**
  action is available only when the connected peer advertises support; it also
  works for read-only users. Refresh replaces existing pixels, including alpha,
  and resynchronizes the browser's previous-frame backing buffers.
- A failed image decode releases its drawing task and schedules bounded
  automatic snapshot recovery. Failed tiles share one deferred recovery timer.
  The server accepts at most one request per user every five seconds; the
  browser spaces requests by at least 5.5 seconds and permits at most three
  automatic requests per connection. Manual refresh remains available subject
  to the same interval. Reconnection resets capability, counters, and deferred
  work. Server snapshot preparation waits at most 250 ms for the render-state
  condition; committed-frame locking, PNG encoding, and socket writes retain
  their normal behavior and transport timeouts.
- The fallback image-stream path reserves its drawing position before stream
  EOF, so faster later streams cannot overtake it. Cancellation detaches stream
  and image callbacks. A confirmed late-EOF regression is covered: a callback
  saved before cancellation can no longer create an image or revive a canceled
  task after a display import/disconnect. Decoder resources are released on
  success, failure, cancellation, and synchronous construction errors.
- The optional performance overlay adds queued frames, oldest queued-frame age,
  waiting-for-image state, image decode failures, and refresh-request counts.
  It continues to report the actual WebSocket/HTTP transport. Diagnostics retain
  numeric state without image, clipboard, or input contents. Enable **Display →
  Show performance statistics** in the Guacamole menu.
- Encoding parallelism can be configured through the administrative environment
  setting `GUAC_DISPLAY_WORKER_THREADS=auto` or a decimal count from 1 through
  64. Invalid values warn and fall back to automatic selection. Affinity-aware
  automatic selection is bounded to 1–64 workers; allocation and thread creation
  are checked, partial pools track only valid handles, and a zero-worker pool
  stops the session instead of leaving graphical work waiting indefinitely.
  Oberon's existing automatic selection remains **22 workers**; no live
  environment override is introduced.

Refresh the browser and reconnect to load the new client and negotiate snapshot
support. Existing **macrdp 0.1.12** remains compatible. This release changes only
Guacamole; it requires no macrdp changes or new DMG. Snapshot recovery depends on
guacd having current committed pixels, and the effect on real remote desktop
work remains user acceptance testing.

## Validation

- Final native CUnit suites: **173 passed**, including refresh instruction
  validation/rate limiting, snapshot alpha handling and render-busy behavior,
  and worker-count/allocation/thread-creation failures. The first native build
  exposed a test parser assumption; this was corrected before the final build.
  No image from a failed build was deployed.
- Java tests: **56 passed**. Browser suites: **102 passed in Firefox** during
  the image build and **102 passed in Chrome** locally. New coverage exercises
  drawing order, catch-up yielding, image cancellation/failure, late fallback
  EOF, negotiated recovery limits, and cleanup.
- Frontend Node tests: **15 passed**, covering clipboard synchronization and
  ordered/coalesced input. Real AngularJS fixtures passed **10 refresh UI** and
  **6 diagnostics rendering/lifecycle** checks; the diagnostics overlay
  screenshot was visually inspected.
- Seven worker selection/lifecycle tests also passed locally with
  undefined-behavior sanitization. The benchmark C harness passed a strict
  local syntax check before running the actual codecs on Oberon.
- Isolated preflight passed existing mounts, numeric UID/GID checks,
  configuration readability, web-to-guacd connectivity, HTTP/language API
  startup (16 languages), and an RDP plugin handshake. It used no published
  ports and opened no real desktop.
- Cutover confirmed the expected private.4 image IDs, unchanged configuration
  and runtime settings, language API availability (16 languages), and guacd
  version 1.6.1. Guacd is healthy, the web container is running, both have zero
  restarts and no OOM kill, and filtered startup logs show no error, assertion,
  crash, or permission exception. New common-js recovery/queue statistics,
  frontend input queue, Refresh display templates, diagnostics, and English
  translations were served and hashed into `served-assets.json`. The original
  private.3 rollback image IDs were verified, and preflight containers removed.

The browser overlay's queue age measures local queued work; update gaps include
idle periods. These values are not network round-trip time or measured input
latency. Real LAN/Wi-Fi/WAN session comparisons remain necessary to assess the
combined effect on scrolling, dragging, pasting, and Show Desktop.

## Encoder parallelism measurements

The isolated Oberon benchmark used the build source above and native build-stage
image `sha256:5090b8299a666d3e84dd5e3dde3decaca85475bba5747502eb036d3c18bd15aa`.
Actual libguac PNG/JPEG/WebP encoders serialized synthetic tiles to one shared
discard socket. Each case used five warm-up frames and 30 measured frames.
Cells below are completion **p50 / p95 in milliseconds**:

| Synthetic update | 2 workers | 4 workers | 8 workers | 22 workers |
| --- | ---: | ---: | ---: | ---: |
| Small text | 0.606 / 0.810 | 0.475 / 0.787 | 0.595 / 0.726 | 0.592 / 0.734 |
| Text scrolling | 10.525 / 11.901 | 6.285 / 8.359 | 5.289 / 5.851 | 10.922 / 12.472 |
| Mixed 4K desktop | 63.326 / 67.754 | 36.319 / 45.326 | 25.547 / 35.884 | 22.022 / 25.691 |
| 4K wallpaper, WebP | 153.116 / 189.681 | 80.316 / 86.585 | 49.511 / 51.181 | 39.338 / 44.482 |

Eight workers completed text scrolling fastest, while 22 completed large 4K
updates fastest at higher CPU/memory cost. Automatic selection remains unchanged.
This single synthetic run isolates encoders and shared serialization, uses a
separate benchmark wakeup barrier, and is subject to host scheduling. It does
not measure the production planner/FIFO, capture/RDP decode, browser painting,
Wi-Fi, or input latency, and does not justify changing the live default.

The full method, configuration details, and resource tradeoffs are documented
in [`docs/encoder-workers.md`](../docs/encoder-workers.md). Complete sanitized
results are in
[`1.6.1-private.4-encoder-benchmark.json`](1.6.1-private.4-encoder-benchmark.json).
