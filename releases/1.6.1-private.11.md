## Changes

### Exact early-exit image classification

The PNG/WebP/JPEG selector stops reading pixels only after its existing
repetition decision is mathematically certain. It still counts horizontal
adjacent RGB pairs independently per row, ignores alpha/unused high bytes,
and preserves the historical initial different-pair bias. With same/different
counts S/D, the existing nonnegative score is exactly S >= 4D. Remaining-work
bounds allow an early result without sampling, reusing a prior decision or
changing the codec policy. Ambiguous rows continue scanning.

Checked comparison budgets and wide counters remove the old signed overflow
in 256*S for large repetitive regions. Division by four avoids scaled-counter
overflow. Empty/one-column behavior and padded, nonzero-origin, bottom-reaching
views are preserved; traversal does not advance beyond the last row. No
source pixel is modified, memory retained, clock read or production counter
added. The row observer is compiled only into a test copy.

In deterministic 100-row fixtures, all-different content reads 20 rows and
all-equal content reads 81. These are structural counts, not frame-speed claims.
Codec eligibility, requested quality, forced-lossless behavior, tiling,
geometry, worker admission, drawing order and acknowledgements are unchanged.
The old overflow's undefined result is corrected rather than preserved.

### Lossless PNG compression study; production defaults retained

Add benchmark-only controls for default/1/3 deflate levels, default/None/Up/Fast
filters and diagnostic RLE. Configuration is validated once before workers or
fork; no runtime environment knob or production PNG API is introduced. The
hook applies only to indexed PNGs, forwarding the real pinned libpng. Per-image
IHDR/TLS coverage and numeric counts verify the requested settings. Final
comparison gates separately protect unchanged Cairo-fallback bytes/fingerprints,
including mixed indexed/fallback workloads.

All twelve production experiments and their negative results are retained.
Faster deflate and alternate filters did not provide a convincing CPU/frame
benefit after payload growth. Existing PNG compression/filter defaults,
full-color/ARGB Cairo fallback and pixel quality therefore remain unchanged.
One patterned export favored Fast filtering, while production text workloads
increased bytes without a consistent CPU/frame benefit; the release does not
choose policy from that fixture.

### Complete browser image-pipeline replay

Add a separate bounded loopback sender exercising the real WebSocketTunnel,
receive pump, Parser, Client, image-stream/Base64 handling, native decoder,
canvas drawing and outgoing sync ACKs. Replay production-generated PNG/WebP
full-window and 40/128-tile frames, with multiple blobs, fragmented instruction
lengths/payloads, source pacing and healthy/LAN/constrained/jitter byte profiles.
No production browser module or instrumentation changes.

Native exports bind exact image/source/generator hashes, verify unchanged
source pixels and independently decode PNG against the deterministic RGB
formula. Browser verification separately checks every template frame's exact
RGBA, draw order and ACKs; timing passes check final RGBA and every draw/ACK.
Canonical references must match across compared payloads. WebP reference modes
are selected strictly by actual VideoFrame.format, never by pixel similarity or
tolerance; the native reference is not an independent decoder algorithm.

Bounded observers report achieved rates/gaps, source schedule debt, transfer,
decode-plus-backlog/draw/ACK intervals, queue age/growth and browser task
opportunities. Sender/browser clocks are not subtracted. Decoder/VideoFrame,
channel/socket/browser resources are released on success and failure. Keepalive
replies cannot interleave inside a fragmented instruction, and client metadata,
protocol/oracle storage and retained observations are capped.

See [classification](../docs/exact-codec-classification.md),
[PNG study](../docs/png-compression-study.md) and
[browser replay](../docs/browser-image-pipeline.md).

## Browser delivery evidence

The same-client/same-payload control runs six cases across four profiles with
four alternating samples: **192 timed and twelve verification runs**, 2,304
measured frames and 279,134,208 exact checked canvas pixels. Both labels are
identical execution slots, not different client software. Their mean per-run
browser p95 differences range from -6.60% to +2.93%, demonstrating control
variability rather than a receiver optimization.

The level1 PNG payload study runs another **96 timed and six verification
runs**, 1,152 measured frames and 139,567,104 exact checked canvas pixels. Ten
PNG assets grow from 14,012 to 22,545 bytes (+60.90%). In the constrained profile,
scheduled-source-due to ACK p95 grows 41.202→57.406 ms (+39.33%) for PNG40 and
504.452→592.169 ms (+17.39%) for PNG128. Other intervals are mixed as changed
sizes alter fragmentation/jitter alignment and decode overlaps transfer.
This strengthens the decision to keep production compression defaults.

All twenty final native-image assets match the baseline's encoded bytes,
SHA256, source RGB hashes, geometry and placements. The identical-payload
control therefore covers the final emitted fixtures without implying a
runtime planner/native-speed comparison. Drawing/ACK order and exact pixels
pass across every run, including recorded per-image decoder modes.

Achieved rates/gaps and actual release errors are retained. The 16 ms source
schedule is a target: the control has 45 starts more than 0.51 ms early, worst
1.474 ms. Scheduled-source-due to ACK is a schedule/backlog proxy, not actual
capture latency. Low display queue depth can coexist with seconds of unsent
source-schedule debt. ACKs travel unshaped over loopback; shaping does not
emulate Wi-Fi loss/retransmission, RTT or congestion. Task probes are not
physical input, and canvas/API completion is not physical paint/FPS. Observer
work adds benchmark overhead; phase aggregates overlap and are not additive.
P95 summaries average four short per-run quantiles, not pooled percentiles.
The readable record references both complete original raw records in adjacent
deterministic gzip files, with compressed/uncompressed hashes; no observations
are removed. [Complete browser record](1.6.1-private.11-browser-image-pipeline-benchmark.json).
