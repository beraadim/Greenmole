# 1.6.1-private.15: stabilize desktop-size AVC444 browser decoding

Synthetic reproduction at the reported 2560×1264 desktop exposed a browser
hardware-decoder problem: one stream stalled before presentation and another
altered chroma samples. AVC444 now requests software H.264 decoding for both
its support probe and actual configuration. GPU color reconstruction remains
active, AVC420 keeps its existing decoder policy, and queue/deadline limits are
unchanged. This can increase browser CPU use relative to hardware AVC420.

The browser's image-fallback status now includes a plain-language reason for
AVC444 failures. Content-free codes distinguish invalid framing, unsupported
codec configuration, decoder errors, native YUV layout/copy failures, GPU
reconstruction/context failures, deadlines, queue limits and presentation errors.
The gateway maps only exact allowlisted failure acknowledgments to static log
messages. Arbitrary browser errors, payloads and acknowledgment text are neither
retained nor logged.

The existing image fallback and safety deadlines remain active. Selecting
AVC444 does not promise that a platform's actual desktop-size decoder exposes
native YUV samples merely because a small support probe succeeds. The matching
macrdp 0.1.20 build also repairs its missing/delayed AVC444 pair handling and
warning flood; use both builds when testing this report.

## Validation

The frozen native image passes 285 tests in each configuration: normal,
diagnostics enabled and pthread diagnostics-TLS fallback. This includes the
exact-code failure acknowledgment allowlist and existing AVC444 primitives.
Chrome passes 247 cases with zero skipped, including small/cropped and actual
2560×1264 software/VideoToolbox streams, full-color references, predictive
auxiliary frames, forced main IDR resets, ownership, deadlines and privacy.
All 40 frontend tests and the production build pass. The pinned client image
passes Maven Java/license/frontend/browser checks; Firefox passes 244 cases and
skips three unsupported WebCodecs/WebGL capability cases covered by Chrome.

The exact runtime guacd and minified browser bundle pass all four synthetic
end-to-end cases: AVC444/AVC420 with both VideoToolbox and OpenH264. Each presents
12 acknowledged frames, injects a decoder failure, verifies a fresh image
repaint and reconnects without video capability. Both AVC444 cases expose the
`decoder-error` reason in client statistics and the gateway's static diagnostic.
AVC444 fine-color mean absolute error is 0.96–1.38 during video and 1.27–1.28 after
native image recovery. The deployed bundle hash matches all four cases.

The matching macrdp 0.1.20 passes 720 Rust tests, eight Python and eight JavaScript
tests plus CLI, TypeScript and production frontend checks; six existing opt-in
cases remain ignored. The actual-resolution native probe completes 12 pairs
without errors or empty output after its asynchronous-pair repair. These are
synthetic compatibility checks, not a live-session performance measurement.
