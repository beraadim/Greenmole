# Greenmole 1.6.1-greenmole.8

Pan desktop now turns off when the native keyboard is dismissed. This includes
the iPad keyboard's own dismiss button, which can leave the text editor focused:
after an observed software-keyboard occlusion, restoration of the viewing area
ends Pan mode. Leaving the editor also ends Pan mode. **Show keyboard** enables
it again, including when reopening an already-focused editor.

The change is limited to the Pan lifecycle. The permanent keyboard strip,
desktop resolution, zoom, mouse defaults and saved preferences are unchanged.
Viewport tracking remains event-driven, with no idle polling.

[Build inputs](1.6.1-greenmole.8.json) retain the dependency commits and base image
digests from Greenmole.7. Apache licenses, attribution and upstream notices are
preserved. Server codecs and browser video transport are unchanged.

## Validation and deployment

Both pinned Linux/amd64 runtime images were built from immutable source
`d5271151b01596902f3a3ef8eed3685713118b1c`. Validation passed:

- 129 frontend Node tests, including seven new viewport lifecycle regressions.
  They cover settled dismissal with residual browser chrome, opening animations,
  manual Pan changes, pinch/rotation, subscriber consistency and timer cleanup.
- 296 native tests, 64 Java unit tests and 256 Firefox browser tests. Three
  existing browser-capability skips and three existing webpack bundle-size
  warnings remain.
- Isolated packaged gateway checks: 16 effective locale versions, byte-identical
  mascot assets, browser video/fallback APIs, RDP plugin selection and
  web-to-guacd connectivity.
- Full-client Chromium and WebKit checks using the compiled page controller,
  production template, tiled display and native keyboard controls. Dismissing
  the keyboard without blurring its editor disables Pan and restores Touchpad
  input. Explicit Show enables Pan again; ordinary blur also ends it. Manual
  Pan remains available after dismissal. Remote dimensions and manual 1.25 zoom
  remain unchanged, with no JavaScript errors or tunnel requests.
- Anonymous live desktop/mobile login checks passed with the correct version,
  responsive layout, mascot and icons, and no JavaScript errors. Screenshots
  passed visual review and temporary forwarding was removed.
- Attribution verification: 92 modification notices, 213 unchanged upstream legal
  files and both reachable imported histories. Source scanning found no new
  secrets; existing flags remain unchanged upstream examples or identifiers.

Browser tests used headless engines with emulated iPad navigator and viewport
geometry and a synthetic display/transport. They did not authenticate or open
an RDP connection. Actual iPadOS browser chrome and software-keyboard behavior
still require device testing. Detection uses an observed keyboard occlusion
followed by viewport restoration; a floating or hardware keyboard may provide
no such geometry signal. All owned test containers, networks and forwarding
resources were removed; production stayed unchanged during isolated checks.

Greenmole.8 is deployed on Oberon. Only the two gateway image references changed;
configuration, runtime settings and unrelated containers were preserved. The
running pair matches the tested images. Guacd is healthy, the web API responds,
and startup checks show zero restarts, no OOM termination and no critical errors.
The Greenmole.7 image pair remains tagged for rollback.

[The validation record](1.6.1-greenmole.8-validation.json) contains exact source
and image identities, asset hashes and sanitized checks. Images were not
published to a registry. Private configuration, credentials and raw runtime
logs are excluded. The common-JS source tree and packaged bundle match
Greenmole.7; this input lifecycle release did not repeat the unchanged four-case
video matrix recorded for [private.16](1.6.1-private.16-validation.json).
