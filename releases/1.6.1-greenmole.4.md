# Greenmole 1.6.1-greenmole.4

This release improves native keyboard use on iPad and other touch devices.
Choose **Input method → Native keyboard** in the connection menu to enable a
compact keyboard control. The preference is stored in the current browser.
An iPad recommendation includes devices using desktop browsing mode, while the
option remains available manually on other devices. Existing input-method
preferences remain unchanged until the user selects the new mode.

The keyboard control focuses a real text input directly from its tap handler,
so the browser can show its native software keyboard. Users can dismiss it
without automatic reopening. Text composition and hardware keyboard input use
the existing text-input translation path.

The visible area responds to the browser's visual viewport, including the space
occupied by the software keyboard. Keyboard opening and closing preserve the
remote display resolution while adapting the local view. Pinch zoom remains
under user control. Event-driven viewport tracking replaces the former 10 ms
polling loop. These changes do not detect remote application text fields
or force a keyboard to open from asynchronous remote events.

[Build inputs](1.6.1-greenmole.4.json) retain the dependency commits and base image
digests from Greenmole.3. Apache licenses, attribution and upstream notices are
preserved. The mascot, video decoding choices, image fallback, protocol names
and authentication/extension configuration remain compatible.

## Validation and deployment

Both pinned Linux/amd64 runtime images were built from immutable source
`05f96d0db8936853abd9a9ace4f113b29f417d3f` and deployed after approval.
Validation passed:

- 296 native tests, 68 frontend Node tests and 64 Java unit tests.
- 25 new frontend regressions: 12 for native-keyboard detection, focus, dismissal,
  Unicode/composition input, shortcut release and saved preferences; 13 for
  viewport geometry, keyboard occlusion, rotation, pinch zoom and cleanup.
- 256 Firefox browser tests, with three existing browser-capability skips.
  Production frontend compilation passed with three existing bundle-size warnings.
- Isolated packaged gateway checks using synthetic configuration: all 16 effective
  locale versions, four mascot PNGs byte-identical to source, login CSS,
  browser video/fallback APIs, RDP plugin selection and web-to-guacd connectivity.
- The packaged Angular application passed anonymous browser checks of keyboard
  controls, synchronous focus from a trusted gesture, hide/reopen behavior,
  Unicode/composition input, shortcut cleanup, narrow layouts, stable remote
  dimensions, pinch/rotation geometry and viewport listener cleanup.
- Anonymous checks of the deployed login passed on desktop and mobile: version,
  96-pixel mascot, login fields, transparent favicons, icon reset and responsive
  layout, with no JavaScript errors. Both screenshots passed visual review.
- Attribution verification: 91 modification notices, 213 unchanged upstream legal
  files and both reachable imported histories.

The keyboard browser checks used desktop Chromium with emulated iPad navigator
and visual-viewport geometry. They did not authenticate or connect to RDP, and
actual iPadOS Safari software-keyboard appearance remains unverified. Real-device
keyboard presentation and remote-session behavior still need user testing.
Fixture-owned temporary containers, networks and forwarding resources were
removed; the running deployment was unchanged during the isolated checks.

Only the gateway image references changed during deployment. Existing
configuration and runtime settings were preserved, as were unrelated containers.
The Greenmole.3 image pair remains tagged for rollback. Both deployed images match
the tested images; guacd is healthy, the web API responds, and startup checks show
zero restarts, no OOM termination and no critical errors.

[The validation record](1.6.1-greenmole.4-validation.json) contains exact source
and image identities, asset hashes and sanitized checks. No images were published
to a container registry; private configuration, credentials and runtime logs are
excluded. The video common-JS bundle is unchanged from the validated baseline;
this input/viewport release did not repeat the full four-case AVC playback and
fallback matrix recorded for [private.16](1.6.1-private.16-validation.json).
