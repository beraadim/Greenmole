# 1.6.1-private.5

Built and deployed on Oberon on 2026-10-15, replacing `1.6.1-private.4` in the
existing `windows11-guac-lab` Compose project. This hotfix addresses slow
browser catch-up and delayed input after clipboard resynchronization. Final
post-cutover verification passed. This remains an internal build of Apache's
unreleased 1.6.1 staging baseline.

## Changes

- Browser rendering continues through a reusable `MessageChannel` instead of
  a chain of zero-delay timers. Private.4's nested timers incurred browser
  timer clamping while draining a backlog, delaying subsequent frames and
  acknowledgements. Rendering still yields after eight milliseconds or
  sixteen complete frames, preserves frame order and atomicity, and gives
  other browser tasks opportunities to run. A timer fallback remains for
  unavailable or failed channels; cancellation closes the ports and invalidates
  queued continuations so stale work cannot resume a new display queue.
- Overlapping clipboard resynchronization requests share one complete local
  read and publication. Publishing clipboard data that was just read locally
  no longer writes the same data back to the browser clipboard. This removes
  a redundant, potentially delayed or permission-gated operation from the
  input wait. Clicks, releases, dragging, keyboard input, and paste ordering
  continue through the existing ordered input queue.
- Actual RDP snapshot requests now log an INFO start record and their result
  with elapsed milliseconds. This distinguishes an in-progress snapshot from
  a session that requested none, without logging image, clipboard, or input
  contents. This is a diagnostic change only; snapshot behavior and rate limits
  remain unchanged.

The timer regression was reproduced independently. It is not conclusive proof
of the cause of the reported slow window switches in the real session.
Image-failure and refresh-request counters were unavailable during that
report, so snapshot activity could not be excluded. The additional log records
support diagnosis if the symptom persists.

## Browser backlog measurements

The repeatable [`benchmark-browser-render.mjs`](../scripts/benchmark-browser-render.mjs)
replays the actual `Display.js` from private.3, private.4, and this hotfix using
synthetic drawing costs and one initial asynchronous blocker. Four samples per
version ran in Chrome 155 on macOS ARM64 with real browser scheduling and no
virtual time. Median backlog completion times, in milliseconds:

| Synthetic backlog | private.3 | private.4 | Hotfix |
| --- | ---: | ---: | ---: |
| 180 cheap frames | 54.05 | 77.20 | 54.75 |
| 40 medium frames | 80.05 | 120.40 | 80.00 |
| 16 expensive frames | 144.00 | 211.15 | 144.00 |

The hotfix retained private.4's early opportunity for a separate queued task
to run: approximately 5.3, 8.0, and 9.0 ms for these cases, respectively.
Private.3 drained each complete backlog before that task ran. These are
synthetic event-loop measurements, not physical input latency, canvas
throughput, a live RDP connection, Wi-Fi performance, or background-tab
throttling. Complete samples and source hashes are in
[`1.6.1-private.5-browser-render-benchmark.json`](1.6.1-private.5-browser-render-benchmark.json).
The benchmark's modified working-tree `Display.js` hash matches the committed
build source below.

## Validation and deployment

Both image builds exited successfully. Native CUnit suites passed **173 tests**;
the web image passed **56 Java tests**, **108 Firefox browser tests**, and
**17 frontend Node tests**. Local checks also passed **108 Chrome browser
tests** and **17 frontend Node tests**.

Isolated preflight passed configuration readability, web-to-guacd connectivity,
HTTP/language API startup (16 languages), and an RDP plugin handshake. It
opened no real desktop. Cutover confirmed the expected private.5 image IDs,
unchanged configuration and runtime settings, 16 available languages, and
guacd version 1.6.1.

The replacement containers started at `2026-10-15T12:16:58Z`. Guacd is healthy;
the web application returns HTTP 200 and 16 languages. Both containers have
zero restarts, no OOM kill, and the expected source-revision labels. Filtered
startup logs contain no ERROR-level entry, assertion, crash, or permission
exception; the web log does contain an authentication WARN for a failed login
attempt. All preflight containers were removed.

Twelve served script/style assets were fetched and hashed into private
`served-assets.json`. Verification confirmed the deployed MessageChannel
continuation, queue statistics, refresh API, and direct-publication clipboard
resynchronization. All four private.4 rollback/private.3 fallback image IDs
below were verified. Operational `verification-result.json`, build/deployment
scripts, and logs remain outside Git in the private release state directory.

Only the two Compose image references changed. Existing **macrdp 0.1.12**
remains compatible; this Guacamole hotfix requires no macrdp package change.

Refresh the browser and reconnect to load the updated client.
No live desktop QA was performed during deployment. Real scrolling, dragging,
pasting, and window-switching comparison remains necessary to confirm the
user-visible result.
