containers in the `windows11-guac-lab` Compose project. This is an internal

## Validation

- Native tests: 123 passed, no failures or errors.
- Java tests: 56 passed, no failures, errors, or skips.
- Firefox browser tests: 15 passed.
- Isolated containers successfully started using the existing mounted
  configuration without publishing ports. Verified numeric user/group IDs,
  configuration readability, HTTP language discovery, web-to-guacd TCP access,
  and the RDP plugin's initial Guacamole protocol handshake.
- After cutover, guacd reported 1.6.1 and was healthy; the web root and REST
  language endpoint returned HTTP 200. Neither container had restarted or
  logged startup errors at verification.

The checks do not open a desktop session or reproduce the original concurrent
display-layer failure. Real browser/RDP session testing remains necessary.

mounts, application environment, network aliases, published ports, runtime
users, and restart policies were verified unchanged. Authentication remains
file-based; no database migration was needed. Shared-drive data was not moved.

## Build transfer correction

An initial preflight rejected images whose entrypoint permissions had been
restricted during source archive extraction. Those images were never deployed.
The source archive was extracted again with permissions preserved and both
images rebuilt and retested. The build driver now rejects entrypoints that
unprivileged runtime users cannot read and execute.
