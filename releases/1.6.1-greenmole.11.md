# Greenmole 1.6.1-greenmole.11

Browser AVC startup now uses a small presentation window instead of immediately
filling its sixteen-frame safety limit. AVC420 begins with four access units;
paired AVC444 begins with two. After the first ordered presentation ACK, steady
windows of eight and four respectively provide bounded pipelining.

When presentation falls behind, the RDP graphics producer waits for ACK progress
within the oldest outstanding frame's existing two-second deadline. This
backpressure lets transient bursts recover without permanently selecting images.
It does not drop reference frames, skip delta pictures, restart a decoder, add an
unbounded queue or change the GAV1/GAV2 wire format. The sixteen-frame and sixteen
MiB hard limits remain. A genuine stall, invalid ACK, unsupported operation,
sharing/recording requirement or decoder failure still uses the existing image
baseline recovery. This is recovery before failure, not automatic video restart
after permanent image fallback.

Browser frame deadlines begin when work is submitted to the decoder, rather
than while encoded frames wait in the bounded FIFO. Actual codec configuration
has its own two-second deadline. Disposal clears queued encoded data, scheduled
display tasks, timers and native frames. AVC420 failure ACKs now carry a small
allowlist of content-free causes, as AVC444 already does.

Gateway diagnostics identify browser readiness, first presentation and bounded
pacing/recovery episodes with queue counts, bytes and oldest age. They do not log
peer-provided text or image contents. These distinguish startup, transport and
presentation pressure without treating graphics ACK latency as a network ping.

## Native keyboard controls

The keyboard button now toggles the device keyboard and shows a pressed
indicator like Pan desktop. The separate Hide keyboard button is replaced by
**Scroll wheel**. With Scroll wheel selected, dragging a finger on the desktop
sends remote wheel events instead of moving the pointer or panning the local
view. Vertical and horizontal scrolling use real RDP wheel input.

Pan desktop and Scroll wheel are mutually exclusive. Pan retains local pinch
zoom and movement in both directions; Scroll wheel operates the remote
application at the current pointer. Gesture cancellation and connection changes
discard unfinished input instead of replaying it into a different session.
The bar keeps measured layout, accessible labels, pressed states and minimum
44-pixel touch targets. Settings access and native keyboard viewport handling
remain available.

See [Native device keyboard](../docs/native-keyboard.md) and the
[AVC420 guide](../docs/experimental-avc420.md) for usage. Both Linux/amd64 images
use [the existing pinned dependencies](1.6.1-greenmole.11.json). Licenses, notices,
upstream history and ordinary image connections are preserved.
