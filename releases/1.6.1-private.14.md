# 1.6.1-private.14: experimental AVC444 browser reconstruction

Adds an explicit AVC444 choice to the Display menu while preserving existing
AVC420 opt-ins and ordinary image connections. Use the matching macrdp 0.1.19
build and select Full color (AVC444) on the server. See the
[activation and fallback guide](../docs/experimental-avc444.md).

## Changes

- Advertise AVC444 only after browser opt-in and a bounded actual
  decode/native-YUV-copy/WebGL rendering probe. Keep AVC420 separately available
  when the host is still configured for standard color detail.
- Send a bounded GAV2 envelope with ordered main/auxiliary H.264 access units and
  their region metadata. Use one decoder for their shared reference chain.
- Reconstruct AVC444 v1 directly from I420/NV12 planes on the GPU, preserving
  one-pixel chroma detail before full-range BT.709 conversion. Handle platform
  allocation padding independently of the encoded macroblock rectangle.
- Retain ordered display tasks, presentation acknowledgments, bounded queues,
  copy/decode/presentation deadlines and complete image recovery. Dispose native
  frames, pending work and GPU resources on failure, reset and disconnection.
- Keep the complete FreeRDP image baseline. Partial regions, single-view
  refinement, AVC444 v2, unsupported operations, recording and sharing remain on
  images. A fallback stays on images until the client reconnects.
- Correct two AVC444 defects in the source-pinned FreeRDP SSSE3 primitives:
  auxiliary chroma stores targeted even instead of odd columns, and the shared
  inverse filter skipped half of each vector block. Retain SIMD acceleration;
  apply only a source- and patch-checksummed correction to the reviewed pin.
  Compare actual installed optimized/scalar planes and RGB pixels for v1/v2,
  including scalar tails. The regression fails 7,037 of 25,801 assertions before
  the fixes and passes all assertions afterward.
- Show the actual codec in playback status. The new Images / AVC420 / AVC444
  choice preserves saved legacy preferences and does not opt in other browsers.

## Validation

The final native suite passes 284 tests in each of three isolated configurations:
normal, diagnostics enabled and pthread diagnostics-TLS fallback. The installed
primitive regression passes all 25,801 assertions for both AVC444 versions.
Chrome passes 241 Jasmine cases with zero skipped, including actual paired
software/hardware decoding, YUV reconstruction, allocation padding, deadlines,
malformed streams, GPU loss and frame ownership. All 40 frontend Node tests and
the production build pass. The tested Maven image passes Java/license/browser
checks; headless Firefox passes 238 cases and skips three unavailable
WebCodecs/WebGL capability cases covered by the required Chrome gate.

The final guacd runtime image and exact minified browser bundle pass four
synthetic end-to-end cases: AVC444 and AVC420, each with OpenH264 and
VideoToolbox. Each presents 12 acknowledged video frames, injects a decoder
failure, confirms fresh image paints, then reconnects without video capability.
AVC444 one-pixel chroma mean absolute errors are 0.92–1.17 during browser video
and 1.08–1.09 after native image recovery. The image-only reconnect also passes.
The deployed common-JS hash matches every packaged integration test.

The matching macrdp 0.1.19 final source passes 706 Rust tests, eight Python and
eight JavaScript tests, with six existing opt-in tests ignored, plus CLI,
TypeScript and frontend builds. It includes the reconnect correction needed to
apply Full color without a server restart. These tests do not measure a live
session's speed. See the [validation record](1.6.1-private.14-validation.json).
