# 1.6.1-private.16: reduce video packet handling overhead

Both video players use native Base64-to-byte decoding when the browser provides
it, with bulk byte copies into the existing bounded frame parser. Older browsers
retain the established decoder. The gateway sends compressed video in the
protocol's standard maximum blob size instead of smaller private chunks,
reducing browser blob dispatches and Base64 operations without changing frame
contents, ordering, deadlines, queue limits or fallback behavior.

Validation and isolated build/preflight results will be recorded after release
checks. Existing production configuration is outside Git.

The matching macrdp 0.1.21 test package independently removes a redundant
post-encode capture discard. The server already coalesces capture backlog in a
latest-only mailbox; the extra skip could discard an otherwise current update.

This candidate is prepared and tested separately from production. Oberon
continues to run private.15 until deployment is requested. Pinning, native tests,
real-browser checks, exact packaged-bundle integration and read-only preflight
results are recorded with the finished build.

Source-level validation passed 259 Chrome browser tests with no skips, 40
frontend tests, the production frontend build and 286 native tests in an
isolated build stage. New regressions cover native and legacy Base64 decoding,
arbitrary envelope boundaries, malformed/oversized inputs, both codecs and
payloads around the protocol's 6048-byte chunk boundary. The new native
regression fails against the original 4096-byte sender while the prior 285
native tests continue passing.

A synthetic actual-source parser benchmark measured 44–55% lower parser-stage
CPU time in modern Chrome; it excludes codec decode, rendering and network work.
Six public synthetic 2560×1264 AVC444 pairs required 40 blob calls instead of 58
for each encoder (about 31% fewer calls, including frame headers). These are
stage/packet results, not a claim of equivalent session FPS improvement. Older
browsers keep the legacy Base64 path and can still benefit from larger blobs.
See the [performance review](../docs/performance-review-2026-10.md) for complete
measurements, limitations and candidates that failed the measurement gate.
