# 1.6.1-private.3

Built and deployed on Oberon on 2026-10-15, replacing `1.6.1-private.2` in the
existing `windows11-guac-lab` Compose project. This remains an internal build
of Apache's unreleased 1.6.1 staging baseline.

## Changes

- RDP source-frame starts and ends now gate both render scheduling and pending
  display snapshots. This avoids exposing an unfinished marked frame through
  either the render loop or a worker retry. Surface-frame acknowledgements
  remain tied to end markers. Resize and teardown reset the gate; missing end
  markers, including repeated starts, expire the open-frame gate after 100 ms
  so they cannot hold output indefinitely. Startup callbacks tolerate the
  interval before the display render thread exists.
- Unmarked updates use recent graphical update gaps to extend the quiet
  window, capped at 12 ms, within a 32 ms batching budget. Isolated updates
  retain the previous 10 ms delay. Cursor movement does not extend graphical
  batching, client backpressure is retained, and shutdown interrupts waits.
  The longer wait can group more tiles into one update under moderate jitter;
  it deliberately trades some first-update latency for better coherence.
- Stable display snapshots copy only the clipped, refined dirty bounding
  rectangle. Initial snapshots, changed dimensions/stride and replaced or
  reattached backing buffers still receive a full copy. Bounds and offset
  arithmetic are checked, and rows outside the changed region remain intact.
- The optional diagnostics overlay adds images and image payload KiB per
  Guacamole update, update-gap p50/p95, browser-processing p95, and reported
  source frames per update. **Guacamole frames/s** and **Source frames/s**
  replace the previous ambiguous FPS labels. Enable **Display → Show
  performance statistics** in the Guacamole menu. Collection stops when
  disabled or destroyed; the five-second numeric history is capped at 256
  observations and retains no instruction or image contents.
- TRACE diagnostics report snapshot bytes copied and aggregate scheduler
  batches, source/coalesced counts, closure reasons and batch-gap percentiles.
  Aggregate scheduling reports occur no more than once every ten seconds;
  their gap histogram caps values at 100 ms. Scheduler batch counts are not
  outgoing Guacamole frames or physical browser paints.

Refresh the browser and reconnect after deployment to load the new client.
Browser assets have new content hashes/build identifiers.

The explicit boundary path pairs with **macrdp 0.1.12**, source
`80fea0da89821accf34db174740b2e86f2ffcd62`. That release sends one negotiated
frame-marker pair across all regions and encoded partitions of a capture when
the selected codec uses RDP Surface Commands and the client advertises marker
support. Classic BitmapUpdate keeps its existing wire format and benefits
from adaptive grouping instead. The macrdp DMG is installed and tested by the
user; deploying Guacamole does not replace the running Mac server.

## Validation

- Native CUnit suites: 159 passed. New coverage includes source-frame gates,
  missing/repeated markers, worker flushes, adaptive scheduling, clipped dirty
  copies, backing-buffer changes and RDP callback acknowledgements.
- Java tests: 56 passed, no failures, errors or skips.
- Browser suites: all 65 passed in Chrome 155 and Firefox 158, including eight
  new frame-metrics tests. A real AngularJS directive fixture passed six
  rendering/lifecycle checks and its overlay screenshot was visually inspected.
- Dirty-copy tests also passed with undefined-behavior sanitization locally.
- Isolated preflight with the existing mounted configuration passed HTTP
  startup, numeric UID/GID checks, configuration readability, web-to-guacd
  connectivity and an RDP plugin handshake. No ports were published by
  preflight, and no real desktop was opened.
- Cutover verified the expected image IDs and preserved configuration and
  runtime settings. After cutover, the web root, language API (16 languages),
  new JavaScript, template and translation assets served successfully; asset
  hashes were recorded in `served-assets.json`. Guacd is healthy, the web
  container is running, both have zero restarts and no OOM kill, and filtered
  startup logs show no error, assertion, crash or permission exception. Build,
  preflight and deployment results remain in the private operational record
  below.

The repeatable comparison in `scripts/benchmark-render-grouping.py` compiles
the real private.2 and current render loops against the same virtual clock
and tile arrivals. It does not contact a service:

| Synthetic arrival trace | private.2 first batch | private.3 first batch |
| --- | --- | --- |
| Unmarked tiles at 0/8/16/24 ms | 10 ms, 2 of 4 tiles received | 32 ms, 4 of 4 tiles received |
| Marked tiles at 0/18/36 ms, end at 47 ms | 10 ms, 1 of 3 tiles received | 47 ms, 3 of 3 tiles received |
| Isolated unmarked update | 10 ms | 10 ms |

These results demonstrate the intended batching tradeoff, not overall session
speed. The dirty-copy byte reduction is workload-dependent: a 160×90 dirty
rectangle on a stable 3840×2160, four-byte-per-pixel framebuffer copies 57,600
bytes instead of 33,177,600; a full-screen change still requires a full copy.

Overlay gaps include idle periods and are not network RTT or input latency.
Processing p95 is based on browser flush-stat samples, not every sync or a
physical screen refresh. Source-frame counts are unavailable when the source
does not report them. Protocol throughput excludes transport headers, TLS and
transport compression; base64-decoded image payload bytes exclude file/audio
streams. Real desktop workloads over the same LAN/Wi-Fi/WAN remain user
acceptance testing; no overall FPS, input-latency or Wi-Fi throughput speedup
is claimed.
