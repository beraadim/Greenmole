# Greenmole 1.6.1-greenmole.12

The optional performance overlay now separates local AVC420 assembly,
encoded/configuration queue, decoder-output and ordered-display time. Each
stage reports a cumulative average and maximum; fixed queue gauges remain
available through the client API. This helps investigate a high gateway
presentation-ACK age without mistaking it for Safari decoder time or a visible
stall.

Collection runs only while **Display → Show performance statistics** or the
existing local pipeline API is explicitly enabled. It retains fixed numeric
aggregates and no frame contents, history, addresses or hardware identifiers;
it sends no measurements to the server. Disabling collection clears unfinished
samples and totals. Stream and connection changes invalidate late callbacks.
The overlay wraps within narrow phone viewports and preserves collection an
embedded application independently enabled.

Playback settings are unchanged: credit windows, decoder slots, H.264 reference
ordering, queue limits, two-second deadlines and image fallback are preserved.
This is diagnostic support, with no claimed playback performance gain. See
[the timing guide](../docs/display-timing-diagnostics.md).

Only the Linux/amd64 web image is rebuilt. The existing Greenmole.11 guacd image
is retained at the immutable ID recorded in [the release inputs](1.6.1-greenmole.12.json).
The web build uses the existing pinned base images and dependencies with Maven
tests enabled. Apache licenses, attribution and upstream history are preserved.

Source validation passes 286 Chrome Jasmine checks including real AVC420/AVC444
WebCodecs playback, 179 frontend Node checks and the production webpack build
with its three existing bundle warnings. Actual Angular directive/template/CSS
rendering passes at 320 and 390 CSS pixels with long timing values, translated
bindings, explicit collection opt-in and teardown. Physical iPhone Safari
behavior remains a device acceptance check.
