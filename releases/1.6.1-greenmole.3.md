# Greenmole 1.6.1-greenmole.3

This release corrects two initial viewport sizing races. The browser could use
an outdated viewport measurement for its connection handshake after the page
layout changed. It now remeasures the current viewport at the waiting and connected
transitions before enabling queued size updates. On the RDP side, deferred
display negotiation could let an older resize overwrite a newer requested
viewport; the pending resize now retains the latest request and waits for server
Display Control capabilities before sending it. Unsent requests do not consume the
resize throttle, while failed sends remain eligible for rate-limited retry.
Together these changes keep initial desktop sizing aligned with the current
browser viewport while preserving subsequent resizing.

The cute green mole login logo and browser icons are retained. Protocol names,
authentication and extension configuration, video decoding choices and image
fallback settings remain compatible. The visible application version advances
to `1.6.1-greenmole.3`.

[Build inputs](1.6.1-greenmole.3.json) retain every dependency commit and base
image digest from Greenmole.2. The release version and distinct downstream image
tags advance together. Apache licenses, attribution and upstream NOTICE files
are preserved.

## Validation and deployment

Both pinned Linux/amd64 runtime images were built from immutable source
`670279dd43a3cb92e7335cc56844b46caf364cc7`. Validation passed:

- 296 native tests, including ten new display-channel regressions for pending
  sizes, capability readiness, throttling, failed sends, disconnect and reconnect.
  The concurrent case races 2,000 browser viewport updates against 1,000 channel,
  capability and disconnect cycles, checking consistent dimensions, ready-channel
  sends and preservation of the final requested viewport.
- 43 frontend Node tests, including three new actual-directive resize regressions.
  The waiting/connected transition cases fail against the original browser code;
  the third covers deferred unknown dimensions and teardown cancellation.
- 64 Java unit tests and 256 Firefox browser tests, with three existing
  browser-capability skips. Production frontend compilation passed with three
  existing bundle-size warnings.
- Isolated packaged gateway checks using synthetic configuration: all 16 effective
  locale versions, the four mascot PNGs byte-identical to source, login CSS,
  browser video/fallback APIs, RDP plugin selection and web-to-guacd connectivity.
  Temporary containers and the internal network were removed after testing.
- Attribution verification: 86 modification notices, 213 unchanged upstream legal
  files and both reachable imported histories.

The client tests and Maven build ran at
`1a5ca3e8fe8fd5369abe6e1d281b057ac92ccc20`. Only native synchronization changed
afterward: the final source has a byte-identical client Git tree, and its client
image reused that validated build cache with identical runtime filesystem
layers. These results apply to the same client source and output; they do not
represent a second independent Maven test run. Native validation and isolated
packaged checks use the final source and image identities above.

Following user authorization, the tested Greenmole.3 image pair was deployed.
Configuration files, runtime settings and unrelated containers were verified
unchanged. Both services are ready, with zero restarts, no out-of-memory kills
and no critical startup log messages. The Greenmole.2 image pair is retained
under explicit rollback tags. No images were published to a container registry,
and no private configuration, credentials or runtime logs are included in the
source evidence.

Anonymous live browser checks also passed: the new version, login form, mascot
and browser icons render correctly on desktop and mobile, with no JavaScript
errors or horizontal overflow. These checks do not authenticate or open a remote
desktop session.

Hard-refresh the browser and fully reconnect to load the new startup sizing
behavior. No macrdp application update is needed for this gateway release.

[The validation record](1.6.1-greenmole.3-validation.json) contains the exact source
and image identities, client-test provenance, asset hashes and sanitized checks.
Video transport remains the previously validated private.16 baseline; this
resize release did not repeat the full four-case video playback/fallback matrix.
