# Greenmole 1.6.1-greenmole.2

Greenmole's new logo is a cute green mole with a pink nose and digging paws.
The login screen uses a 96-pixel logo, with transparent PNG derivatives for
browser icons, touch icons and the README. The original transparent artwork,
asset paths and generation prompt are documented in [branding notes](../docs/branding.md).
The old letter-based SVG mark is removed.

This release carries the protocol, video decoding, image fallback, connection
recovery and performance behavior already validated through
[private.16](1.6.1-private.16-validation.json). Configuration keys, extension
identifiers and supported connection settings remain compatible. The visible
application version advances to `1.6.1-greenmole.2`.

[Build inputs](1.6.1-greenmole.2.json) retain the dependency commits and base
image digests from Greenmole.1; only the release version and distinct downstream
image tags change. Apache licenses, attribution and upstream NOTICE files are
preserved.

## Validation and deployment

The pinned Linux/amd64 image pair was built from source revision
`65086c58efffdb7526eec91b2295c5a93b4622d1` and deployed successfully.

Validation passed:

- 286 native tests, 64 Java unit tests and 40 frontend Node tests.
- 256 Firefox browser tests, with three existing browser-capability skips.
- Production frontend compilation, with three existing bundle-size warnings.
- Isolated packaged gateway checks using synthetic configuration: 16 effective
  locale versions, all four mascot PNGs byte-identical to source, transparent
  RGBA images with the expected dimensions, login CSS, browser video/fallback
  APIs, RDP plugin selection and web-to-guacd connectivity.
- Headless Chrome checks of the deployed anonymous login on desktop and mobile:
  the 96-pixel mascot, version, login fields, transparent favicons, dynamic icon
  reset and mobile layout all passed with no JavaScript errors.
- Attribution verification: 83 modification notices, 213 unchanged upstream legal
  files and both reachable imported histories.

Only the guacd and web image references changed in the deployment configuration.
Private configuration files and runtime mounts, environment, ports, networks,
users, security options, resource limits and restart policies were preserved.
Unrelated containers were unchanged. The previous private.16 image pair and a
private configuration backup remain available for rollback. Both new containers
were running without restarts or OOM termination; guacd was healthy, the web API
responded, and startup logs contained no critical errors.

[The validation record](1.6.1-greenmole.2-validation.json) records the exact source,
image IDs, mascot hashes and sanitized checks. Private configuration, credentials,
logs and operational addresses are excluded. Images were built locally on the
gateway host and were not published to a container registry. Video transport
behavior remains the previously validated private.16 baseline; this branding
release did not repeat the full four-case video playback/fallback matrix.
