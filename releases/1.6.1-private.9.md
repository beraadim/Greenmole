# 1.6.1-private.9

Deployed to Oberon on **16 October 2026 at 11:05:07 CEST**
(09:05:07 UTC). The existing connection configuration and runtime
settings are verified unchanged.

## Changes

- Reduce the per-image cost of optional display diagnostics. Configure tests
  compiler-managed thread-local pointer storage, first `_Thread_local` and then
  `__thread`, using the caller's compiler flags and strict warnings. It compiles
  and links the probe without running a target executable, preserving cross
  compilation, and restores the caller's `CFLAGS`. Supporting builds read, bind,
  and clear the current synchronous encoder sample without the previous
  `pthread_once`/`pthread_getspecific` path or an owned pthread slot. Other
  compilers retain the existing pthread backend, destructor, and failure
  handling. Diagnostics remain disabled by default, add no diagnostic clock
  reads when disabled, and still have a per-image lookup and per-blob branch.
  This reduces specific work; it does not imply zero overhead.
- Replace indexed PNG's row table plus one allocation per row with one checked
  allocation containing the aligned pointer table and palette-index bytes.
  Acquiring the block before `setjmp()` keeps the cleanup pointer valid across
  libpng `longjmp()` errors. Both libpng structure-creation failures, output
  errors, and success release the block. Row-storage OOM now returns an error
  without a null dereference; palette OOM follows the existing Cairo fallback.
  The old error path leaked allocated row storage. Palette insertion order,
  bit-depth thresholds, packing, compression/filter defaults, and buffering are
  unchanged. High-color and non-RGB24 images retain the Cairo path, so reducing
  indexed staging allocations does not imply faster full-color photo PNGs.
- Reuse one lazy, thread-confined packed ARGB input workspace per display
  worker for WebP. Only input storage is retained; every call still initializes
  a fresh `WebPPicture` and releases libwebp-owned conversion/encoder scratch.
  The exported encoder and stream call chain remain intact. The preset remains
  `WEBP_PRESET_DEFAULT`, method 2, thread level 0, with unchanged caller-supplied
  quality and lossless mode. Source pixels are always copied: RGB24's unused
  high byte becomes opaque alpha, while ARGB32 contents and source padding stay
  unchanged. Positive and negative strides and nonzero-origin views are
  preserved. Touched PNG/palette/WebP scans avoid advancing source pointers
  after the last row, including views ending at the backing allocation's bottom.

The WebP workspace grows geometrically and retains at most **2 MiB per worker**:
at most **44 MiB for a 22-worker display pool**, or **128 MiB for a 64-worker
pool**. Allocation is lazy, so these are upper bounds rather than mandatory
allocations. They apply to each pool's retained packed input only; codec scratch,
layer buffers, and transient allocations are excluded. Multiple display pools
can retain their own storage. The limit follows observed private.8 photo image
shapes: the largest sampled input was 491,520 pixels (1,966,080 bytes); a 1 MiB
limit would have excluded many representative images. Eligibility is not a
measurement of actual cache reuse or latency.

Non-worker calls, nested encodes while a workspace is busy, and over-limit
images use transient storage. If rounded workspace growth fails, the old cache
is preserved and the original exact-sized transient allocation is attempted
before failing the image. A worker restores its preceding thread-local binding
and releases its input after the encode loop exits; shutdown joins workers
before their storage can disappear. Platforms without configured compiler TLS
keep WebP calls transient and gain no additional pthread lookup. These choices
bound retained memory and preserve synchronous/reentrant call ownership at the
cost of not reusing every possible input.

Codec selection, requested quality, forced-lossless behavior, operation order,
frame/ACK boundaries, automatic 22-worker pool, and twelve-worker partial-batch
admission policy are unchanged. Lossless WebP retains its existing `exact=0`
behavior for RGB hidden beneath fully transparent alpha; no stronger alpha
guarantee is introduced. No browser implementation, codec setting, normal-path
clock, or Mac package change is included.

See [diagnostics](../docs/display-timing-diagnostics.md),
[PNG storage](../docs/png-row-storage.md),
[WebP ownership and bounds](../docs/webp-workspace.md), and
[production benchmark method](../docs/display-production-benchmark.md).

## Validation

The final exact-source Linux native stage passes **225 tests with diagnostics
off**, **225 again with `GUAC_DISPLAY_DIAGNOSTICS=1`**, and **225 in an actual
whole-library build configured without compiler TLS**. The fallback build uses
the pthread diagnostic backend and transient WebP encoding. These are full
native gates, separate from focused local sanitizer checks.

The native suite adds six forced-pthread diagnostic tests, eight PNG tests,
and ten WebP tests. Diagnostics checks cover disabled behavior, exact numeric
snapshots and saturation, deterministic clock failures, parent/child sample
isolation, fallback allocation/installation failures, infallible clear,
byte/status forwarding, and bounded logs. The forced fallback copy runs even
when the real library uses compiler TLS.

PNG tests use real libpng/Cairo to compare complete payload bytes with legacy
row staging and independently decode every pixel. Coverage includes palette
sizes 1/2/3/4/5/16/17/255/256, odd widths, tall images, padded rows,
bottom-reaching nonzero-origin views, varied RGB24 unused bytes, and unchanged
high-color/ARGB32 Cairo fallback. Fault injection covers palette/row OOM, both
libpng creation failures, early output errors, and a late IDAT `longjmp()` after
a real blob has been sent; all paths release Guacamole-owned staging memory.

WebP tests compare prepared pixels and full lossy/lossless payloads at qualities
0, 75, and 100 using actual libwebp 1.6.0. Independent lossless decoding checks
visible RGB and every alpha value. Tests cover source immutability, changing
dimensions, padding, signed strides, bottom-reaching views, retention limits,
oversized/nested encodes, failed growth with successful transient fallback,
total allocation/encode failures, scoped A-to-B-to-A restoration, thread
isolation, and cleanup.

Owner-reported local validation also passes:

- All twelve selected-plus-forced-pthread diagnostic test functions across five
  strict Clang UBSan configurations: C11 TLS with both clock branches, GNU TLS
  in C99 with a monotonic clock, and pure pthread C99 with both clock branches.
  This local assertion runner uses production diagnostic/FIFO source with the
  existing Darwin-compatible flag fixture. Four strict `-O2` production syntax
  variants and generated test discovery also pass.
- Eight focused PNG tests with `-O2`, strict C99 warnings, and UBSan, including
  the final late-output fault and bottom-reaching view fixtures; strict syntax
  checks also pass.
- Ten focused WebP tests with real libwebp 1.6.0 and UBSan in compiler-TLS and
  no-TLS configurations, repeated 25 times each: **500 test executions**.
  Worker syntax checks pass with WebP enabled and disabled.

The client tree is exactly unchanged from the validated web tree
`fbf17e7ef24db6997d3f013195f05d0bb3962c53`. Its build reuses the cached **56 Java,
171 Firefox common-js, and 33 frontend checks**. Those checks were validated for
the reused client tree; this release adds no browser code or browser-performance
claim.

Separate isolated components use their own earlier identical harness on both
images. The PNG-only comparison against the diagnostic component reduces
scroll/redraw CPU about 30–32%, with approximately 1–2% lower p95. The diagnostic
component comparison is mixed: scroll p95 is about 10% lower, but redraw p95 is
about 2% higher and small-text p95 increases by about 0.094 ms. Text CPU changes
are around +1–7.5%. This does not establish zero diagnostic overhead or an
isolated universal TLS speedup. Absolute timings from different harnesses are
not compared directly.

The separate preparation-only test uses the compiled candidate helper and a
reproduction of private.8 allocation/copy/free, not two full library versions.
Both modes run twice in balanced order, with 5,000 samples and twenty warm-ups
per fixture. All six eligible warmed fixtures make zero measured input
allocations and stay within the cap; the 1025×512 over-limit fixture makes 5,000
transient allocations and retains no cache. Prepared pixels and source
immutability match. This measures initialization, input allocation/copy/free
only, excluding `WebPEncode()`, the FIFO and frame output. Its substantial
preparation reductions are not full-encoder or production-frame speed claims.

Untimed strict protocol replay validates **112 lossless frames and 721,534,976
RGB pixels**, including untouched regions, against the expected canvases. Final
hashes, every planner counter and worker admission match private.8. Separate
short fixed PNG, lossy WebP75 and lossless WebP75 runs compare encoded payload
fingerprints across versions; all match. Fingerprints use per-image FNV-1a64
over encoded bytes, aggregated as per-codec sum and XOR: non-cryptographic
multiset evidence, not a proof of image positions/order or security. Enabled
hash runs add per-byte work and are excluded from all performance tables.

Diagnostic-on fixed WebP/PNG probes independently verify numeric worker
statistics. They remain separate from normal default-off performance records;
overlapping wall-time sums are not standalone codec CPU or network latency.
Diagnostics stay disabled in the deployment.

The [complete sanitized record](1.6.1-private.9-display-production-benchmark.json)
retains raw orders, follow-ups, component controls, preparation tests, encoded
fingerprints, diagnostic probes and source/image/harness identities. All
production-path fixtures are synthetic and unpaced. They omit capture, RDP
transport, Wi-Fi, browser painting, physical input and live frame pacing.
Live responsiveness remains a user-acceptance check.
