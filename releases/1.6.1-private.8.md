# 1.6.1-private.8

Deployed to Oberon on **16 October 2026 at 09:49:00 CEST**
(`2026-10-16T07:49:00Z`), preserving the existing configuration.
This release retains the private Apache Guacamole staging/1.6.1 baseline and
Oberon's existing connection configuration, resize/browser behavior, 22-worker
automatic pool and twelve-worker partial-batch admission policy.

## Changes

- Restore portable native C optimization. The build helper's include-only
  `CFLAGS` suppressed Autoconf's optimization default; private.7's actual
  libguac Makefile had no optimization option. Unset flags now default to
  `-O2`, with the dependency include path appended. Explicit custom or empty
  diagnostic flags remain authoritative. The shared helper also affects
  source-built C dependencies; their source pins and distribution codec
  packages are unchanged. No host-specific ISA flags or fast-math are enabled.
- Reject empty copy-search buckets through an exact 8 KiB membership bitmap
  before accessing the 1 MiB index. Full-hash and exact-pixel checks, collision
  handling, scan order, row-boundary exhaustion, image fallback and counters
  remain unchanged. Cached/transient plans own and clear their own membership.
- Add opt-in numeric display timing diagnostics and controlled photo benchmarks.
  Diagnostics separate batch admission, committed-frame lock wait, format
  selection, image streaming, nested blob sends and final frame completion.
  They are disabled in this deployment. TLS/clock failures invalidate snapshots
  safely; enabled summaries are bounded to one per ten seconds per display.
  Benchmark-only codec/quality controls work against old and new libraries and
  reject mismatched realized codec/pixel/payload-byte-count work.

Production quality, codec selection, forced lossless behavior, frame boundaries
and operation ordering are unchanged. No codec hysteresis is introduced:
unpaced synthetic format changes are not evidence of live instability.
No Mac package changed; existing macrdp 0.1.12 remains compatible.
See [compiler flags](../docs/native-build-optimization.md),
[copy planner](../docs/display-planner.md),
[diagnostics](../docs/display-timing-diagnostics.md), and
[benchmark method](../docs/display-production-benchmark.md).

## Validation

The final pinned native stage passes **201 tests**, and all 201 pass again with
`GUAC_DISPLAY_DIAGNOSTICS=1`. Three new bitmap tests cover collisions, boundary
bits, all 65,536 occupied buckets and cache/transient lifetimes. Six diagnostic
regressions cover disabled behavior, saturation, deterministic timing, clock/TLS
faults, thread isolation, byte/status forwarding and logging bounds. Local UBSan
checks include 375 planner test executions and both diagnostic clock branches.

The client tree is exactly unchanged from the tested private.7 web build
(`fbf17e7ef24db6997d3f013195f05d0bb3962c53`); the matched image reuses that
validated build cache with the new implementation source label. That cached
build passed 56 Java, 171 Firefox common-js and 33 frontend checks.
No new browser implementation or browser-performance claim is included.

The forward production replay checks **112 lossless frames and 721,534,976 RGB
pixels**, including untouched pixels, with matching expected canvases and final
hashes. Every planner counter matches private.7 except retained scratch gauges,
which increase by exactly 8192 bytes. Worker admission matches. Reverse timing
runs explicitly disable replay; fixed-photo and diagnostic runs also disable
replay and rely on the separate correctness gate. All four codec controls pass
short runtime smoke tests with one-frame lossless replay.

The bitmap itself is compared against the separately built optimized control
`f50dc7636`, rather than attributing the compiler improvement to it. Balanced
60-frame tests reduce scrolling/redraw p95 approximately 6–7%; every planner
counter matches and retained scratch adds 8 KiB. A late-copy order-sensitive
outlier was followed by a reversed balanced 180-frame probe, with no sustained
regression. Those experiments use their own identical earlier harness on both
images and must not be compared directly to the final instrumented timings.

**Default-off cost:** a separate equal-PNG B/A/A/B 60-frame comparison of the
optimized bitmap candidate `c8cd99e79` with final `277bc0321` reports scrolling
p95 +4.76% (21.838 to 22.878 ms), redraw +1.98%, mixed 4K +1.29%, small text
-8.98% and small photo -2.36%. Scrolling/redraw CPU is +3.61%/+2.60%; other
CPU differences are 0.04–1.44%. Default-off diagnostics add no clocks, but
retain per-image TLS lookups and branches. This probe does not establish zero
overhead or a universal bound. The final version still improves all balanced
workloads against deployed private.7 as shown above.

Separate diagnostic-on fixed-format photo runs validate real worker counters
against independently observed codec/pixel/blob counts. Queue buildup is
concentrated in full-desktop batches. Stream envelopes dominate this local
discard-socket fixture; they include codec/protocol/socket work, with blob time
nested inside them. Parallel sums overlap, and the fixed-format hook bypasses
the classifier. These are not pure encoder CPU or network-delivery measurements.
Diagnostic runs use different sample/warm-up sequences and are not an on/off
overhead pair.

The [complete sanitized record](1.6.1-private.8-display-production-benchmark.json)
retains both orders, fixed photo controls, diagnostic data, default-off overhead,
optimized bitmap experiments, image/source identities and harness hashes.
All measurements are synthetic, unpaced server planning/FIFO/encoding/protocol
work. They do not establish capture, RDP transport, browser paint/FPS, Wi-Fi or
physical-input latency; live responsiveness remains for user acceptance.
