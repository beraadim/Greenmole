# Greenmole 1.6.1-greenmole.16

This release addresses the 25 Maven dependency alerts found when GitHub
refreshed Greenmole's dependency graph. The five earlier npm alerts were
automatically marked fixed after that refresh.

## Dependency changes

- Remove the obsolete proprietary Tomcat 7 WebSocket adapter and its Catalina
  and Coyote 7.0.37 compile dependencies. These two dependencies account for
  23 alerts. They were marked `provided` and were not bundled in the deployed
  web application. The standard JSR-356 WebSocket endpoint and HTTP tunnel
  fallback remain unchanged, as do the existing Jetty adapters. Installations
  requiring Tomcat 7's proprietary WebSocket API must use a container with
  standard WebSocket support. The standard Servlet API 3.1 is declared
  explicitly with `provided` scope for compilation and remains excluded from
  the packaged application.
- Update the minifier plugin's Plexus Utils override from 3.5.1 to 3.6.1,
  which fixes GHSA-6fmv-xxpf-w3cw. This is a build dependency. Other Maven
  plugins have separate dependency realms; this targeted update does not
  assert that every inherited build dependency has been upgraded.
- Remove the unused Commons Lang 2.6 dependency from the optional RADIUS
  extension, addressing GHSA-j288-q9x7-2f5v. Its existing protocol choices
  and cryptographic dependency versions are unchanged.

The standard Docker release continues to omit LGPL extensions, including
RADIUS. The optional RADIUS package and dependency graph are validated separately
with `-P lgpl-extensions` and tests enabled for the prerequisite modules.
Container base images, native dependency pins, connection configuration,
browser input and video behavior are unchanged.

### Existing optional RADIUS runtime limitation

A separate protocol-loading and loopback PAP authentication probe exposed a
pre-existing incompatibility between JRadius 1.1.5 and modern Bouncy Castle:
JRadius eagerly initializes its TLS authenticators, which reference the removed
`DERObjectIdentifier` class. This also prevents PAP authentication from starting.
The same failure was reproduced with the previous Commons Lang 2.6 dependency
restored. Removing Lang 2 does not cause or fix that failure.

RADIUS compilation and packaging are not a certification of working RADIUS
authentication. Do not deploy this optional extension until its JRadius
integration is modernized and runtime-tested. This release does not downgrade
cryptography or alter authentication protocols to conceal the incompatibility;
the normal Docker images continue to exclude the RADIUS extension.

## Validation and attribution

The [validation record](1.6.1-greenmole.16-validation.json) records the optional
RADIUS build, Maven and browser test results, packaged tunnel checks, image
identities, dependency inspection and deployment configuration comparisons.
Packaged tunnel tests use isolated synthetic authentication and do not connect
to a user's remote desktop.

All original license and notice files remain intact. The attribution manifest
now explicitly records retired source files and their original Git blob IDs;
the original source and copyright notices remain in the reachable upstream
history. Missing or modified license and notice files still fail validation.
