# 1.6.1-private.13: experimental AVC420 browser decoding

This internal release adds an explicit browser-local AVC420 experiment for the
matching macrdp 0.1.16 build. Existing connections keep the image path unless
that browser opts in and passes a secure-context WebCodecs support probe.
See [activation, transport and fallback details](../docs/experimental-avc420.md).

## Changes

- Forward supported full-desktop AVC420 access units through existing Guacamole
  streams for ordered browser decoding, cropping coded macroblock padding.
- Gate native H.264 negotiation and built-in browser playback independently;
  an unrelated connection cannot inherit another client's permission.
- Preserve FreeRDP software decoding for the shadow image recovery baseline.
  This first version removes active video's image encode/decode stages, not the
  gateway's native H.264 decode cost.
- Retain the initial IDR until the browser is ready. Do not suppress images until
  a video frame is presented. Drain old image work before opening video.
- Bound payloads, byte retention, in-flight work, sequence values and playback
  deadlines. Keep a larger encoded FIFO than decoder submission slots so normal
  network bursts do not trigger fallback or drop dependent frames.
- Close decoders, cancel ordered tasks and release frames on errors and lifecycle
  changes. Sharing, recording, resize, unsupported drawing, explicit refresh or
  playback failure retain or restore images. An unconditional PNG and backing
  copy refresh reconciles images even when the desktop returns to an old state.
- Build FreeRDP with source-pinned OpenH264 2.6.0, including its runtime license.
  Explicitly keep AVC disabled for ordinary browser connections.
- Add Display opt-in, reconnect guidance and waiting/playing/fallback status.

The image/video barrier has a 250 ms retry polling budget. Existing frame locks
and socket operations keep their normal deadlines; this is not a hard total
250 ms bound on a full snapshot or a blocked network write.

## Validation

The native production callback/state/stream and worker-ordering suites passed
278 tests in each of three isolated no-network configurations: normal,
diagnostics enabled and pthread diagnostics-TLS fallback. Cases cover initial image seeds,
aligned coded versus mapped dimensions, real ACK handling and deadlines, mixed
frames, classic paint suppression scope, shared-user/recording exclusion and
restoring image A after video B when ordinary image comparison would send none.

The browser suite passed 203 Jasmine tests in isolated Chrome with zero pending.
It includes actual WebCodecs decoding of 24 real synthetic OpenH264/VideoToolbox
access units, IDR/P/forced-IDR sequences, visible cropping, pixel checks and image
fallback. All 37 frontend Node tests and the production webpack build passed.

`scripts/test-avc420-e2e.mjs` passed the additional synthetic RDP/FreeRDP/Guacamole/
real Chrome release gate for both OpenH264 and VideoToolbox through the final
guacd runtime image and the exact packaged, minified browser bundle. Each case
presented 12 acknowledged video frames, injected a decoder failure, verified two
fresh native image paints and then reconnected without video capability. The
ordinary connection received no private video streams. Sampled color differences
were at most three channel levels across video and images. These checks exposed
and verified macrdp's corresponding full-range BT.709 correction.

The fixture server uses public synthetic credentials and disposable TLS on
loopback. It never captures a desktop or accepts input. Test containers, the
fixture server and temporary SSH forwards were removed after validation.
See the sanitized [validation record](1.6.1-private.13-validation.json).
These checks do not establish a measured live performance improvement.

## Delivery

Build inputs are pinned in `1.6.1-private.13.json`. Deployment replaces only the
two Guacamole image references. Operational configuration backups, raw logs,
container metadata and rollback material remain in private Oberon state outside
Git.

Deployed on Oberon on 2026-10-17, replacing private.12. Only the guacd and web
image references changed. Configuration content and runtime environment, users,
mounts, ports, network aliases and restart policy were verified unchanged. The
gateway is healthy, both containers have zero restarts and no critical startup
entries, and 16 web languages remain available. Served assets include the new
checkbox, status/help text, per-client gate and decoder. The served common-JS
hash matches the exact bundle used in both integration tests.

The runtime images are built from frozen source revision
`a7539eb9dd4a6f8c73da9a335c3e854496c55f42`. Later commits tighten synthetic tests
and record delivery; they do not change runtime code. The prior private.12
images remain tagged for rollback. See the sanitized
[deployment record](1.6.1-private.13-deployment.json).
